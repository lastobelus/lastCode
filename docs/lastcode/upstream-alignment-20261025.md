# Upstream alignment review for October 2026 (PT)

**Status as of 2026-10-26 PT:** The source analysis is complete, including the accepted Astra and Opus findings. Installed 3717.1 already includes most former import recommendations and all seven original repairs. Release-specific acceptance remains incomplete. This is a static review and acceptance document; execution receipts, private evidence and active coordination stay external.

## Outcome

LastCode's architecture holds up against upstream. Most LastCode services do jobs upstream does not do, so we keep them. Nothing here calls for new architecture, a new framework, a compatibility layer or a second coordinator.

The installed release already includes most of what earlier reviews asked to import. Keep LastCode's architecture. There are three things to do next:

1. Make older threads with unfinished work reachable in the sidebar: first reproduce the source risk, then repair it if confirmed.
2. Verify and update the bundled tunnel connector. Upstream describes this as a security fix; the advisory and selected runtime binary remain unverified.
3. Bring in the 83 new upstream commits carefully, then test that release. Two of them are risky: the MCP tool merge and the timeline move.

**What we have not shown yet:**

- Source inclusion does not establish installed package contents, runtime behavior or fresh acceptance. Old test results do not prove 3717.1 or a future checkpoint.
- The LastCode shelf/open-obligation gap is a source risk to reproduce, not observed loss. Direct navigation still loads unlisted thread details; omission is not deletion.
- No human judgment has passed. Two checks are prepared: Pause/held Action and lineage/sidebar. Actual long-sleep/reopen is neither prepared nor passed.
- Native mobile, unattended shared authentication, entire originating-session loss, and LAN/relay/tunnel results remain separate unpassed acceptance boundaries.

**Acceptance condition:** The seven original repairs remain merged with their recorded focused checks, independent reviews and exact-tree CI evidence. Any selected release needs its own affected automated checks and integrated pass, recording source, fixture and runtime. Keep deferred human judgments explicit. Installation, source ancestry and a version label do not pass those gates.

## Ranked recommendations

### 1. Older threads with unfinished work should stay reachable in the sidebar

**Why:** the server already leaves older settled threads out of the sidebar list. Its exceptions include pinned, snoozed, live and ancestor rows, but do not check open dashboard items or Action resumes. The LastCode sidebar does not request the omitted page. The #507 banner cannot point at a row that was never loaded. This establishes a source risk; no reviewed runtime reproduction proves that an older open-obligation state is lost from the sidebar.

**Scope:** first reproduce it. Show whether an older settled thread with open work disappears from the LastCode sidebar. Then fix paging and retention at the existing shelf boundary, keeping counts, thread families, live updates and reconnect caching correct. Opening a thread directly still loads it, so omission does not delete it.

**Done when:** a focused failing test, then passing shelf, family and cache tests, a measured LastCode cold-load size, and one real-client run. Upstream's 93% payload figure is not a LastCode measurement. Preserve the appendix's shelf requirements.

### 2. Update the bundled tunnel connector

**Why:** installed source pins cloudflared `2026.10.0`. Upstream [`b6994c549977dd194d38f95902fcfac0445d8fa1`](https://redirect.github.com/pingdotgg/t3code/commit/b6994c549977dd194d38f95902fcfac0445d8fa1) moves to `2026.10.4`, describing removal of compromised eMudhra certificate intermediates. That security rationale is upstream's claim, not an independently confirmed advisory.

**What's known:** all four macOS/Linux download hashes upstream pins match the published release-asset metadata. The macOS checksums in the release notes text are different. No one has confirmed the advisory independently, verified the downloaded bytes in this review, or checked which cloudflared binary a running install actually uses; a supplied binary can override the managed one.

**Scope:** confirm the advisory and verify the downloaded bytes, then carry the version and hash change. Record the version a real install selects. **Done when:** selection and hash tests pass on macOS and Linux and the selected version is recorded, plus a tunnel check if T3 Connect is used. Urgency depends on whether the connector is used.

### 3. Bring in the 83 new upstream commits, then test that release

**Why:** this is the path to new upstream features and fixes, including the Vercel fx provider, ACP notices, goal stop/clear, deleted-worktree recovery and preview fixes. It is also where carries are most likely to break things. Two commits need deliberate handling:

- **MCP tool merge ([`ed44f251d89d4dae2f8dcf11c24fb3dec9dda4c7`](https://redirect.github.com/pingdotgg/t3code/commit/ed44f251d89d4dae2f8dcf11c24fb3dec9dda4c7)).** Upstream merges 18 tools into action tools. For example, `preview_click`, `preview_type` and the other preview input tools become `preview_act`, the `t3_queue_*` tools become `t3_queue`, and fork, merge-back and transfers become `t3_thread_transfer`. LastCode has heavily changed the same files: about 1,700 lines across the MCP server, preview handlers and thread handlers. Risks: renamed tools, LastCode-only tools that do not fit the new shape, and access checks that now run per action.
- **Timeline move ([`bd3287b640a717513a44b1d23e362aed446a263f`](https://redirect.github.com/pingdotgg/t3code/commit/bd3287b640a717513a44b1d23e362aed446a263f)).** Upstream moves thread status from above the composer to the end of the timeline. #507 added LastCode's held-Action banner to the composer, and LastCode has changed the same chat files. Risk: the held-Action banner and LastCode notices get lost or are hidden when scrolling up.

**Scope:** build the next checkpoint on pinned `65b4a69`, carrying LastCode's work. Then rerun only the affected tests and one integrated check on that exact release, recording the SHA, fixture and runtime. Include a valid originating-session-loss run, Pause and Action reopen, signed viewers, return from modals, and retained preview auth.

**Done when:**

- A rename map from old to new MCP tool names exists and has been checked against LastCode's own tools and agent instructions.
- Per-action discovery, invocation and authority tests pass, including captured-run reads. Keep guest and OAuth authority separate; a later client must not replace lost originating-session authority.
- After the timeline move, the #507 banner and LastCode notices are still visible, including discoverability while scrolled away.
- Native, human and actual long-wait cases remain marked not yet run until executed.

These are recommendations, not launched work or authorization for later phases. Only about 13 of the 83 commits were checked file by file. Other changes, including settings regrouping, queued messages and device agents in background threads, were not assessed individually.
